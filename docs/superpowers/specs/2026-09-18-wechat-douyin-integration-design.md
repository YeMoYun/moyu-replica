# 微信 + 抖音正式集成设计

状态：用户已批准三套 UI 和“先打通微信 + 抖音”的实施顺序；本文补充正式功能技术规格，等待书面规格确认。尚未修改正式功能代码。

## 本批目标与边界

首页进入微信伪装模式，呈现已验收的微信布局；通过文件夹按钮将真实抖音网页插入当前会话的播放器气泡，小气泡内直接操作；老板键仅遮挡播放器；配置重启恢复。

- UI 以 `previews/chat-ui` 已验收微信截图版为准，不重新设计导航、头像、会话列表、标题、消息气泡或输入区，不移入外层预览平台切换栏。
- 本批仅微信和抖音。钉钉、飞书、其他站点及五模式统一选择框随后逐批接入；设置中不把尚未实现的站点显示为可用。
- `D:\MoYuMaster-1.0.0-win` 与提取源项目只读；头像和横/竖屏 GIF 仅复制自带素材，不编辑原件。不照搬广告、遥测或支付代码。
- 不改已验收透明视图、控件、设置和行为；公共主进程/preload 仅增加隔离的聊天接口和分派，必须有保护性回归测试。
- 微信、钉钉、飞书均为本地伪装聊天，不登录这些账号，不向真实联系人发送消息。抖音网页可以由用户自行登录；不读取或导出账号凭据。

## 方案与结构

推荐独立微信视图 + 可复用聊天模型 + 气泡播放器组件 + 独立聊天窗口控制器。复用已验收布局及纯数据行为，正式持久化由主进程负责，不依赖预览 localStorage。

不采用把所有功能继续追加到旧 `ChatSkinView.vue` 的方案：旧视图同时服务钉钉，容易串皮肤和状态。也不把整个预览 HTML 作为正式窗口：演示模型和正式存储、guest 生命周期需明确分离。

职责划分：

- 新建微信正式视图，`/wechat` 路由仅切到新视图；旧钉钉路由继续原实现。
- 共享聊天数据模块负责校验、消息/会话操作、尺寸计算、版本化配置和旧数据迁移，不访问 DOM 或 Electron。
- 气泡组件负责 webview、加载状态、页面缩放、遮罩、导航和事件清理，不拥有全局配置。
- 主进程聊天服务负责配置读写、窗口身份检查、旧配置备份和更新广播。
- 独立聊天窗口控制器负责微信窗口的显示、关闭、几何恢复及老板键遮挡状态；微信不进入透明窗口的统一隐藏注册表。
- preload 暴露具名且限定用途的聊天接口，远程 guest 不加载应用 preload、不启用 Node、不得调用聊天 IPC。

仓库当前不是 Git 仓库，不创建 worktree 或提交。保留现有改动，以文件边界、哈希记录和测试追踪本批影响。

## 消息和会话

默认沿用通过验收的七个会话与项目小组三条文字，默认没有播放器。搜索、切换会话、未读清零、头像、成员数、消息时间和草稿可用。

Enter 发送本地文字，Ctrl+Enter 或 Shift+Enter 换行；中文输入法组合输入时 Enter 不误发送。空白消息忽略，单条文字不超过 2000 字。全部文字按文本渲染，不将联系人或消息作为 HTML 执行。

文件夹按钮插入真实抖音播放器，按照当前设置显示为自己或对方发送，不增加虚构的实时在线/已读事实。每个会话最多一个活跃抖音播放器，重复插入定位现有气泡并提示，不累积后台 guest。

切换会话时将已挂载的气泡与 guest 保留在稳定的会话容器中；非当前会话暂停已在播放的视频，恢复显示不自动启动先前由用户暂停的视频。老板键遮挡覆盖所有已挂载会话，防止切换绕过。删除播放器/会话、配置替换或关窗才销毁其 guest。

## 气泡设置和真实网页

右上「更多」保留播放器设置、聊天配置、插入入口；外部点击和 Escape 收起。输入工具栏保持已验收外观，未接入的通话/截屏等操作明确提示，不假装控制真实微信。

- 站点本批固定抖音。默认地址为 `https://www.douyin.com/?recommend=1`，允许用户在播放器设置指定抖音 HTTPS 页面；禁止可执行协议、凭据 URL 和非抖音导航目标。
- 横屏基础宽高 220×140，竖屏 160×260，沿用已验收预览尺寸；大小 80–200%，默认 140%，窄窗口按比例限制至聊天内容宽度，不强行放大整个窗口。
- 尺寸和方向变化只调整现有气泡与页面适配，不重新创建 webview、不重新加载当前页面；聊天专属 zoom/CSS 不读取或修改透明模式的偏好。
- 默认关闭交互遮罩，视频网页在小气泡内直接接收鼠标、滚轮和键盘操作，不以窗口放大作为操作前提。开启遮罩时点击可解除当前气泡遮罩，与老板键状态相互独立。
- 页面加载、网络失败、guest 崩溃及地址被拒绝显示真实状态和重试入口，不显示虚构播放成功；取消导航类错误与实际失败区分。
- Electron 31 已销毁 frame 的已知兼容保护仅在微信 guest 新分支安装，不更改透明 guest 现有注册和行为，不用全局异常吞掉其他错误。

## 老板键

沿用应用现有老板键快捷键设置，不引入新系统快捷键。全局触发同时调用现有透明/广告策略和新聊天策略；透明策略本身不修改。

微信窗口保持可见，文字、导航及输入区不变；播放器覆盖源项目本地横/竖屏 GIF，并暂停遮挡前正在播放的视频。webview 仍挂载，遮挡不导航、不改变 DOM 身份、地址或播放进度；恢复时仅尝试继续本批因遮挡而暂停的 video，失败明确反馈，不保证浏览器拒绝 autoplay 时自动播放。

关闭窗口清理注册和订阅；在老板键已开启时新建微信窗口或新插入气泡直接处于遮挡状态，避免短暂露出视频。遮挡属于运行时安全状态，不写入聊天内容配置。

## 配置与持久化

正式配置使用独立 `chatModes.wechat` 命名空间，版本号 1，保存自己的昵称、联系人/群聊及消息、所选会话、草稿、抖音地址、播放器布局和设置。运行时 DOM/guest ID、老板键标志不持久化。聊天配置提供结构化字段与 JSON 导入/导出、恢复默认；JSON 校验后原子替换，保存成功才更新当前界面。

复用现有文件存储的原子写入，不改用户配置文件位置。消息/设置保存失败保留上一个已提交状态并显示失败；并发写入串行化，失效的旧响应不得覆盖新状态。保存成功向当前微信窗口广播一次，避免重复订阅。

首次迁移只读取旧 `wechatConfig` 的联系人和 `名字|内容` 字符串消息，按第一个分隔符归属；未匹配联系人仍保留为独立会话。原始旧配置在同一次原子写入中备份，迁移成功写入新命名空间但不删除旧键。格式无法无损迁移时保留原文件与旧键，显示提示，不静默重置。

旧配置站点若不是抖音，保存原值备份并明确提示本批只支持抖音，使用本批默认地址；不将其他站点冒充抖音。预览 localStorage 不自动覆盖正式配置。

## 入口与验收

第一批沿用首页「微信模式」入口，进入新微信视图；第一次默认选择抖音，之后恢复配置。在视频分组增加明确的「抖音微信模式」入口，传递抖音站点；既有广告/透明入口调用保持不变。统一五模式弹窗不属于本批。

验收链：进入微信 → 文件夹插入 → 抖音网页在气泡内直接操作 → 修改横/竖屏和大小不重载 → 文字发送与会话切换 → 老板键遮挡/恢复同一 guest → 关闭重启恢复聊天配置 → 无新增主进程异常弹窗。

验证分层：

1. 先失败后实现的 Node 测试覆盖校验、迁移、持久化失败/并发、会话/player 生命周期、老板键窗口策略和 URL 限制。
2. 构建与全部现有回归测试；透明视图及其专属模块哈希不变，必要公共分派扩展有混合模式检查。
3. 隔离 userData 的 Electron 本地测试页验证真实 webview 生命周期、操作传递、遮挡恢复、消息发送、菜单、重启恢复和关窗清理；离线通过不等于抖音线上功能已验证。
4. 正式微信截图对照已批准预览；用户在真实抖音页验收登录/播放/滚轮和界面操作。若站点或网络阻止实际播放，记录可观察限制，不把占位视频当作线上成功。

自审：范围限定微信 + 抖音，其他模式独立；布局不再重新设计；视频遮挡与交互遮罩分别建模；旧数据保留；不写只读源或透明设置。规格没有未定参数。
