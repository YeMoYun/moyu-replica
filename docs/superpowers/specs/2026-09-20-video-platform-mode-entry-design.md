# 视频平台五模式入口与跨平台伪装模式设计

日期：2026-09-20  
状态：已完成交互与架构评审，待实施计划

## 1. 目标

将复刻项目主页调整为接近 MoYuMaster 源软件的深色卡片式入口，并为抖音、B站、虎牙、斗鱼、快手统一提供以下五种模式：

1. 广告模式
2. 透明度模式
3. 微信模式
4. 钉钉模式
5. 飞书模式

现有透明度模式已经验收，本次只调整其入口映射，不修改透明度页面、控件、窗口参数或内部行为。

## 2. 范围

### 2.1 本次包含

- 重做主页整体视觉和功能入口布局。
- 视频模式区域保留自定义网站模式、本地视频播放，并加入五个平台入口，共七个入口。
- 五个平台使用统一的五模式选择弹窗。
- 补齐 B站、虎牙、斗鱼、快手的广告模式。
- 为 B站、虎牙、斗鱼、快手接入微信、钉钉、飞书三种伪装界面。
- 隔离每个“视频平台 × 伪装界面”的状态、会话和窗口位置。
- 保持现有抖音广告模式与三套伪装界面的已验收视觉和主要交互。
- 为新增窗口补齐安全校验、错误呈现、老板键和生命周期管理。

### 2.2 本次不包含

- 修改任何已经验收的透明度模式实现。
- 扩展个人中心、客服后台、会员或支付等业务。
- 修改只读源软件目录 `D:\MoYuMaster-1.0.0-win`。
- 让不同视频平台共享网页登录状态或聊天数据。

## 3. 主页与模式选择器

### 3.1 主页布局

主页采用深色背景、居中的 MoYuMaster 标题和三列功能卡片。功能区继续包含阅读模式、网页模式、视频模式、游戏模式、伪装模式和系统设置。

视频模式固定展示：

- 抖音模式
- B站模式
- 虎牙模式
- 斗鱼模式
- 快手模式
- 自定义网站模式
- 本地视频播放

现有其他入口继续连接原有功能。主页换肤不得删除当前可用能力。

### 3.2 五模式弹窗

点击前五个平台时，主页显示居中的模式选择弹窗，背景使用遮罩和模糊效果。标题为“选择{平台名}模式”。按钮按以下顺序排列：

- 第一行：广告模式、透明度模式
- 第二行：微信模式、钉钉模式
- 第三行：飞书模式，横跨整行

弹窗支持：

- 右上角关闭。
- 点击遮罩关闭。
- `Esc` 关闭。
- 选择模式后立即关闭弹窗并打开对应窗口。
- 相同组合已打开时只恢复并聚焦现有窗口，不重复创建。

### 3.3 全局伪装入口

主页伪装模式区域保留微信、钉钉、飞书快捷入口。快捷入口打开该界面最近一次使用的视频平台；没有记录时默认抖音。旧版直接打开抖音伪装模式的行为保持兼容。

## 4. 平台矩阵

建立唯一的平台定义模块，至少包含：

- 稳定平台键：`douyin`、`bilibili`、`huya`、`douyu`、`kuaishou`。
- 中文名称。
- 官方首页地址。
- 允许的官方域名集合。
- 广告模式窗口键和路由。
- 现有透明度模式窗口键和打开方法。
- 三种伪装模式的窗口身份生成规则。

主页、主进程、地址验证和测试必须引用同一份定义，禁止在多个文件重复维护不一致的平台清单。

## 5. 广告模式

### 5.1 共用行为

五个平台的广告模式以已验收的抖音广告模式为标准，复用同一套页面结构、控制器和窗口控制能力，并通过平台定义加载不同网站。

广告模式必须：

- 使用紧凑、置顶的小窗口。
- 允许直接在小窗口内点击和操作网页。
- 提供顶部“← 返回”按钮并返回 webview 的上一级历史页面。
- 提供刷新、设置和关闭等已验收控件。
- 不要求先放大窗口才能操作网页。
- 继续支持老板键、窗口恢复和持久化。

### 5.2 平台差异

平台首页、域名校验、默认缩放和必要的页面样式由平台配置提供。共用控制器不得写死抖音域名。

抖音现有广告模式作为回归基线。对共享代码的改动不得改变其已验收交互。

## 6. 透明度模式保护

主页的透明度按钮只调用当前已有入口：

- 抖音：现有 `douyinOpacity`。
- B站：现有 `bilibiliOpacity`。
- 虎牙：现有 `huyaOpacity`。
- 斗鱼：现有 `douyuOpacity`。
- 快手：现有 `kuaishouOpacity`。

实施前后记录受保护文件哈希，并运行现有透明度测试。除入口调用文件和必要的公共平台定义外，不编辑透明度视图、控制器和平台脚本。

## 7. 微信、钉钉、飞书模式

### 7.1 视图复用

继续复用已经验收的 `WechatView.vue`、`DingTalkView.vue` 和 `FeishuView.vue` 及其样式，不为十五个组合复制十五套页面。

每套视图从可信窗口上下文读取当前视频平台，用于：

- 显示“插入{平台名}播放器”等平台化文案。
- 使用该平台默认地址。
- 校验用户输入地址。
- 选择正确的 webview 持久化分区。

除平台相关文字和播放器来源外，三套 UI 的布局、聊天控件和已验收行为保持一致。

### 7.2 窗口身份

每个组合使用稳定复合身份，例如：

- `chat:bilibili:wechat`
- `chat:huya:dingtalk`
- `chat:kuaishou:feishu`

主进程从发送 IPC 的实际 BrowserWindow 反查组合身份。渲染页面不得通过可修改参数声明自己的权限范围。

### 7.3 数据隔离

以下数据按“视频平台 × 伪装界面”分别保存：

- 聊天状态与修订号。
- 当前播放器地址和播放器设置。
- BrowserWindow 尺寸、位置和覆盖状态。
- webview 的持久化 session 分区。
- 最近使用的平台。

抖音微信、钉钉和飞书继续兼容现有存储键与分区，避免清空已验收数据。其他平台使用新的复合键和分区，例如 `persist:moyu-chat-bilibili-wechat`。

### 7.4 地址与导航安全

每个平台只允许无用户名和密码的官方 HTTP(S) 地址。主页面导航、重定向、新窗口请求和 webview 初始挂载均执行相同的平台域名校验。

拒绝的地址在当前伪装窗口内显示错误，不允许形成未捕获异常或主进程 JavaScript 错误弹窗。

## 8. 窗口与快捷键行为

- 相同组合只允许一个窗口实例。
- 重复打开时恢复、显示并聚焦原窗口。
- 老板键同时覆盖当前打开的广告和伪装窗口。
- 关闭或销毁窗口后，事件监听器不得继续访问已释放的 WebFrameMain。
- 快捷键操作必须跳过已销毁窗口，并把可恢复错误发送到对应渲染窗口。
- 不因新增窗口改变透明度模式的快捷键行为。

## 9. 错误处理

- 主页打开失败时在主页错误栏显示可读错误。
- 地址、分区和平台身份不合法时拒绝操作并保留当前有效状态。
- 保存聊天状态继续使用修订号检测，避免旧窗口覆盖新状态。
- 非法或损坏的持久化数据按现有恢复策略备份后恢复默认值。
- 所有关闭、跳转和异步回调先检查窗口及 webContents 是否已销毁。

## 10. 实施阶段

1. 主页视觉、平台矩阵和五模式选择器。
2. 五个平台入口与窗口身份生成。
3. B站、虎牙、斗鱼、快手广告模式。
4. B站的微信、钉钉、飞书模式。
5. 虎牙的微信、钉钉、飞书模式。
6. 斗鱼的微信、钉钉、飞书模式。
7. 快手的微信、钉钉、飞书模式。
8. 全量回归、构建和验收记录。

每个阶段完成后独立测试，不等待全部平台完成后才验证。

## 11. 测试与验收

### 11.1 自动化测试

- 平台矩阵完整性和键唯一性。
- 首页七入口与每个平台五按钮的渲染和分发。
- 广告地址白名单、返回行为和小窗口直接交互。
- 复合窗口键、存储键和 session 分区生成。
- 五个平台地址校验，包括导航、重定向和 `window.open`。
- 三种伪装皮肤的数据验证和状态修订冲突。
- 老板键、窗口关闭、窗口恢复和销毁后的异步回调。
- 现有透明度、抖音广告、微信、钉钉和飞书回归套件。

### 11.2 手工/Electron 冒烟

逐个平台验证五个模式按钮，并确认：

- 打开正确窗口。
- 重复点击不会创建第二个相同窗口。
- 广告网页可在小窗口内操作且返回有效。
- 微信、钉钉、飞书 UI 与已验收版本一致。
- 不同组合登录态、聊天状态和窗口位置不串联。
- 老板键和恢复正常。
- 关闭过程中无主进程错误弹窗。

### 11.3 完成标准

- 五个平台共 25 个模式入口全部可达。
- 新增的 12 个跨平台伪装组合可独立运行。
- B站、虎牙、斗鱼、快手广告模式达到抖音广告模式的控件和交互标准。
- 现有五个平台透明度模式保持通过，受保护文件哈希未变化。
- 项目完整测试、构建和专项冒烟全部通过。
