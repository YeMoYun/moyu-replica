# 新功能窗口居中与前台显示设计

## 目标

修复从主页打开功能窗口时恢复旧坐标和旧外观状态，导致窗口出现在难以找到的位置、被其他窗口遮挡或保持隐藏的问题。

## 适用范围

- 适用于从主页新建的全部功能窗口，包括广告模式、透明模式、微信/钉钉/飞书模式、阅读模式和其他工具窗口。
- 主窗口自身不套用子窗口状态重置规则。
- 已经存在的功能窗口再次点击入口时，只恢复、移到前台并聚焦，不重新居中或改变当前尺寸。

## 新建窗口行为

每次真正创建一个新的功能窗口时：

1. 从该窗口上次保存的边界中只继承宽度和高度。
2. 宽高限制在目标显示器的工作区内，避免超过可见区域。
3. 忽略上次保存的横纵坐标，居中到鼠标指针所在的显示器；无法取得该显示器时回退到主显示器。
4. 窗口透明度恢复为 100%。
5. 永久置顶恢复为关闭；此次“置顶”只表示打开时临时移到系统窗口层级最前方。
6. 自动隐藏恢复为关闭，鼠标事件恢复正常。
7. 新窗口准备好后按 `show -> moveTop -> focus` 的顺序显示，确保用户能够立即看到并操作。

页面缩放、登录 Cookie、阅读进度、站点地址等内容设置不属于窗口外观状态，继续保留。

## 老板键与安全边界

- 老板键是用户主动触发的全局隐藏状态，不属于需要清除的持久化窗口设置。
- 老板键处于隐藏状态时仍然优先，不能因为新建或重新聚焦窗口而绕过。
- 临时前台显示不会写入“永久置顶”设置，也不会让窗口持续遮挡其他软件。

## 实现结构

新增一个小型主进程窗口打开辅助模块，职责限定为：

- 根据窗口当前宽高和目标工作区计算居中边界；
- 将窗口临时显示到最前并聚焦；
- 不读取业务模式、网页内容或渲染层状态。

`openRoute` 在普通、广告、聊天控制器恢复旧状态以及旧的右下角定位完成后，再统一执行新窗口归一化：

- 使用各控制器现有接口或对应的 `BrowserWindow` 能力，将透明度、永久置顶和自动隐藏恢复为默认值；
- 保留控制器已经校验过的宽高；
- 应用新的居中坐标。

这样可以覆盖三套窗口控制器，同时不重写其尺寸持久化、老板键、全屏、关闭和状态通知逻辑。

## 错误处理

- 多显示器信息不可用时使用主显示器工作区。
- 保存尺寸缺失或无效时使用窗口定义中的默认尺寸。
- 窗口已经销毁时不执行显示或聚焦操作。
- `moveTop` 在测试替身或旧运行环境中不可用时仍执行 `show` 和 `focus`，不阻断窗口打开。

## 验收与回归测试

1. 普通透明窗口保存旧坐标、低透明度、永久置顶和自动隐藏后，重新创建只保留宽高，并居中、100% 不透明、非永久置顶、关闭自动隐藏。
2. 广告窗口保存旧坐标和透明度后，重新创建只保留宽高并居中，不再停留在旧位置或右下角。
3. 微信/钉钉/飞书聊天窗口保存旧坐标后，重新创建只保留宽高并居中。
4. 在第二显示器点击入口时，窗口居中到第二显示器工作区。
5. 新建窗口准备好后调用临时前台显示和聚焦，不写入永久置顶状态。
6. 已存在窗口再次点击入口时不改变其当前位置和尺寸，只恢复并移到前台。
7. 老板键隐藏逻辑、窗口尺寸持久化、透明度控件和各模式入口继续通过现有回归测试。
