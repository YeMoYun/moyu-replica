# 钉钉模式抖音气泡正式集成设计

状态：待用户书面审阅。界面预览已验收；本文只定义第二批正式接入，不代表代码已经实现。

## 目标与边界

将已验收的钉钉预览正式接入 `/dingding`，并复用第一批已经验证的抖音网页气泡、地址同步、播放器适配、消息持久化和老板键遮挡能力。

本批只支持抖音，不加入 B 站、虎牙、快手或阅读网站；不实现真实钉钉账号、联系人、消息、通话、DING、文档、日历或工作台。所有聊天数据明确为本地伪装数据，不向真实联系人发送。

微信模式、飞书预览、广告模式和全部透明度模式保持现有行为。只读源 `D:\MoYuMaster-1.0.0-win` 不写入。

## 已确认的界面

正式界面沿用已验收预览，不重新设计：

- 35px 蓝色顶部栏，左侧账号信息，中间全局搜索；
- 120px 浅色功能导航，显示消息、DING、文档、日历、工作台、通讯录和底部更多；
- 250px 白色会话列表，保留未读数量、时间和消息摘要；
- 50px 聊天标题区，显示头像、名称、成员数和外观动作按钮；
- 白色消息区，自己消息使用浅蓝色气泡并显示本地“已读”状态；
- 底部圆角输入区，Enter 发送，Shift+Enter 换行；文件夹按钮插入抖音气泡；
- 窄窗口使用已验收的会话列表抽屉，不产生页面横向滚动。

默认数据采用预览中的“研发项目组、林晓、设计讨论组、陈晨、文件传输助手”等五个本地会话，但默认不自动联网加载播放器。用户点击文件夹后才在当前会话插入真实抖音气泡；每个会话最多一个播放器，重复点击定位已有气泡。

## 架构选择

采用“共享运行核心 + 独立平台皮肤与数据”的方案。

### 平台配置和状态模型

新增钉钉平台配置，描述默认会话、头像色调、存储键、窗口键和网页分区。现有聊天状态函数改为可接收平台配置，但省略配置时仍严格使用微信默认值，保证现有微信调用与存量数据兼容。

钉钉数据使用：

- 状态：`chatModes.dingtalk`；
- 迁移备份：`chatMigration.dingtalk`；
- 窗口位置：`chatWindows.dingtalk`；
- guest session：`persist:moyu-chat-dingtalk`。

钉钉和微信的消息、草稿、设置、窗口位置、Cookie 与登录状态互不共享。状态仍使用 revision 乐观锁和先校验后写入；磁盘写入失败不发布未提交状态。

### 旧配置迁移

首次启动正式钉钉模式时，如果不存在 `chatModes.dingtalk`，读取旧的 `dingdingConfig` 和 `dingding.currentSiteKey`：

- contacts 和 `姓名|内容` 消息按旧微信迁移规则转换成本地会话；
- 不删除或覆盖旧键，将原值和迁移警告一起备份到 `chatMigration.dingtalk`；
- 旧站点不是抖音时只保留备份并显示一次说明，正式播放器地址使用安全的抖音首页；
- 旧配置畸形时拒绝部分猜测式迁移，加载钉钉默认数据并保留可见警告。

### 正式钉钉视图

新增独立 `DingTalkView.vue` 和钉钉样式文件。它复用排队保存控制器、URL 导航协调器、播放器注入脚本和图标组件，不复制微信页面结构，也不让两套皮肤互相依赖 CSS。

播放器组件增加可选平台参数：默认值继续是微信 partition；钉钉显式传入钉钉 partition。地址必须是无凭据的抖音 HTTPS 页面。加载期间连续改地址、同域重定向、旧导航事件和失败重试沿用已经验证的代次控制；站外主框架跳转和弹窗继续由主进程拒绝。

设置菜单提供抖音地址、横/竖屏、80–200% 大小、自己/对方发送和交互遮罩。配置菜单提供昵称、会话名称、联系人、成员数、头像色调、本地 JSON 导入/导出及恢复钉钉默认数据。非法配置不会覆盖已提交数据。

### 窗口、IPC 与老板键

现有聊天窗口控制器扩展为明确允许 `wechat` 和 `dingtalk`，分别恢复和保存窗口位置；老板键遮挡状态仍为全局状态，因此已经打开的两个聊天窗口会同时遮挡，新打开的钉钉窗口会继承当前遮挡状态。

新增 `dingtalkModeControl` preload 接口与来源校验 IPC。读取、保存、状态和关闭只接受 `/dingding` 窗口；打开只接受主窗口。旧 `dingdingControl`、`dingdingConfigApi` 和 `/dingdingConfig` 暂时保留，避免旧入口立即失效，但新的正式视图不再依赖它们。

首页现有“钉钉模式”按钮继续使用，不新增重复入口。`/dingding` 改为加载正式 `DingTalkView.vue`；微信 `/wechat` 路由和透明度路由不变。

## 交互与数据流

1. 首页打开钉钉窗口，主进程按 `dingtalk` 恢复窗口和遮挡状态。
2. renderer 先读取运行时遮挡状态，再读取或迁移钉钉聊天状态，避免恢复播放器短暂暴露。
3. 用户发送消息、切换会话、修改设置或配置时，客户端按 revision 串行保存；失败保留最后一次已提交界面并显示错误。
4. 插入播放器后创建稳定 message ID；切换会话仅隐藏而不销毁 guest，隐藏时暂停，返回时只恢复此前正在播放的媒体。
5. guest 导航通过钉钉独立 session；最终合法抖音地址写回该消息和钉钉默认地址。
6. 老板键只覆盖播放器区域并暂停媒体，不隐藏窗口、不改变原生 opacity；恢复后仍是同一个 guest。
7. 关闭窗口清理监听器、ResizeObserver 和 guest；再次打开或进程重启后恢复已提交消息、草稿、设置和地址。

## 错误处理与安全

- renderer 不取得 Node 能力，远程抖音页不能访问应用 preload API；
- IPC 按发送窗口路由校验，不允许主窗口读取聊天配置，也不允许钉钉读取微信状态；
- URL 校验同时存在于共享模型和主进程 guest 导航边界；
- 配置采用完整验证和原子替换，限制会话数量、每会话消息数量、文字长度、ID 和头像色调；
- 页面加载、render process 退出、存储失败和版本冲突均显示真实错误，可重试但不重复派发导航；
- 不增加全局异常吞噬逻辑，不以自动化离线页面冒充真实抖音在线播放通过。

## 测试与验收

按测试驱动顺序实施：每项生产改动前先增加会失败的测试并确认失败原因。

1. 纯模型测试：钉钉五会话默认值、平台隔离、消息/草稿、单播放器、设置与 JSON 校验、旧配置迁移和失败写入。
2. 运行时测试：微信/钉钉独立 revision 队列、窗口位置、共同老板键、后打开窗口继承遮挡、关闭清理。
3. 静态接线测试：新路由、preload 来源限制、独立 partition、旧兼容入口和微信路由保持。
4. 实际 Electron smoke：正式布局、输入法与换行、真实 webview 点击/滚轮、缩放不重建 guest、会话切换暂停、地址连续切换、站内重定向、站外阻止、老板键、配置校验、关闭重开和独立进程恢复。
5. 回归：完整 `npm test`、生产构建、微信 20+1 检查、广告模式、抖音及多视频透明模式；比较受保护文件哈希。

自动化使用隔离 userData 和本地 HTTPS fixture，不读取用户账号。完成后由用户在真实网络环境验收抖音登录、推荐流、播放、滚轮和老板键。

## 验收标准

- 正式 `/dingding` 外观与已批准钉钉预览一致；
- 可在小窗口聊天气泡中直接操作真实抖音页面，不需要放大原生窗口；
- 修改布局、切换会话、老板键和配置更新不重建现有 guest；
- 钉钉与微信数据、窗口和网页登录信息完全隔离；
- 重启后恢复已提交状态；错误有可见反馈且不会破坏旧数据；
- 微信模式和所有透明度模式的现有测试及人工外观不回退；
- 真实线上抖音功能只在用户人工验收后标记通过。

## 明确不做

本批不接入飞书，不加入其他视频或阅读站点，不调用真实钉钉服务，不同步云端，不删除旧配置接口，不重构广告或透明度模块，也不修改只读源软件。
