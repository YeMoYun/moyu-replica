# 飞书模式抖音气泡正式集成设计

日期：2026-09-20

## 目标

把已经通过视觉验收的飞书预览迁入正式 Electron 应用，并接入本地消息、配置、持久化、老板键和真实抖音网页气泡。飞书不连接真实飞书账号，不向真实联系人发送消息；抖音网页只在用户主动插入播放器后加载。

微信、钉钉、广告模式和全部透明度模式保持现有行为。只读源 `D:\MoYuMaster-1.0.0-win` 不写入。

## 方案选择

采用“共享聊天内核 + 飞书专属视图”。扩展现有聊天 profile、状态验证、存储服务、窗口控制、播放器和主进程接线，使其明确支持 `feishu`；飞书 UI 由独立 `FeishuView.vue` 和作用域样式实现。

不复制整套钉钉逻辑，避免多个平台分别维护相同的状态队列、导航和安全策略；不把预览页面直接嵌入正式窗口，避免预览状态与正式 Electron 存储形成两套实现。

## 正式入口与隔离边界

- 新增 `/feishu` 路由、独立原生窗口和首页“飞书模式”入口。
- 飞书状态保存为 `chatModes.feishu`，窗口状态保存为 `chatWindows.feishu`。
- 抖音 guest 固定使用 `persist:moyu-chat-feishu`，不得使用微信、钉钉或默认 session。
- `feishu-mode:*` IPC 只允许飞书窗口读写；打开飞书模式只允许主窗口调用。
- 通用设置 IPC 不返回或覆盖飞书聊天状态、迁移备份和窗口状态。
- `will-attach-webview` 同时校验抖音 HTTPS URL、飞书窗口与飞书 partition 的对应关系，并强制关闭 Node、remote preload 和权限请求。
- 微信继续使用 `persist:moyu-chat-wechat`，钉钉继续使用 `persist:moyu-chat-dingtalk`，三者互不共享 cookie、localStorage、消息或配置。

## 飞书默认状态

飞书 profile 使用独立头像词表和通过验收的 10 个默认会话：质检组、林晓、设计讨论组、陈晨、云文档助手、打卡提醒群、小叶的飞书助手、标注临时任务群、考勤通知、协作机器人。质检组默认 16 名成员。

默认状态包含文字消息和一张飞书专属本地媒体卡片。媒体卡片只显示合成标题、说明和本地占位外观，不创建 WebView、不请求网络，也不伪装成真实飞书文件。

飞书状态允许三种消息类型：

- `text`：本地文字消息。
- `media-card`：仅飞书允许的本地静态媒体卡片，无远程地址。
- `player`：用户主动插入的真实抖音网页气泡。

每个会话最多一个 `player`，但可同时保留一个或多个经过上限校验的本地媒体卡片。消息、会话、草稿和配置继续使用现有数量与长度上限。

飞书增加持久化 UI 状态 `ui.hiddenAnnouncements`，记录被用户关闭公告的会话 ID。该字段只允许引用现存会话；重置配置时恢复为空。业务页签当前不持久化，重新打开时回到“消息”。

## 视觉结构

正式视图迁移已验收预览，而不是重新设计：

- 浅蓝灰渐变窗口背景，三栏之间保留 6px 间隔。
- 左侧为 176px 文字导航，包含头像、添加按钮、搜索和飞书功能入口。
- 中间会话栏约占可用舞台的 29%，最小 280px，包含消息标题、三个快捷会话、圆形头像、外部/机器人标签、时间和摘要。
- 右侧聊天区包含 43px 群标题栏、7 个群页签、可关闭/恢复的群公告、消息区和 52px 单行输入栏。
- 群聊显示成员数和机器人数量；消息使用圆形头像、灰色对方气泡和浅蓝自己气泡。
- 本地媒体卡片保持截图中的灰色卡片外观；真实抖音播放器也放在灰色消息卡片容器中。
- 850px 以下压缩导航和会话栏；720px 以下折叠会话栏，由移动按钮展开；页面不产生横向溢出。
- 无边框窗口提供可拖动区域；搜索框、输入框和按钮明确设为不可拖动区域。

## 用户交互

- 顶部搜索过滤本地会话；三个快捷会话按钮真实切换会话。
- Enter 发送，Shift+Enter 与 Ctrl+Enter 换行；输入法合成和 keyCode 229 不发送。
- 草稿按会话保存，切换会话后恢复；未读数在进入会话时清零。
- “消息”页签显示聊天内容。其他页签保留已验收外观并提示“功能未接入”，不会显示虚构业务数据。
- 公告关闭后写入 `ui.hiddenAnnouncements`；点击“群公告”页签可重新显示当前会话公告。
- 输入栏“＋”在当前会话插入真实抖音播放器；重复操作不会生成第二个播放器。
- 播放器设置支持地址、横竖屏、80%–200% 大小、发送方和交互遮罩；尺寸与遮罩变化不重建 guest。
- 聊天配置支持基本字段、完整 JSON 和恢复默认。JSON 校验失败时不覆盖已提交状态。
- 老板键只在原位置遮挡并暂停三个聊天模式的播放器，不隐藏聊天窗口、不修改窗口透明度；恢复时只恢复遮挡前实际播放的媒体。
- 关闭窗口销毁 guest；重新打开和进程重启后恢复已提交的消息、草稿、公告状态、配置和播放器地址。

## 状态损坏与错误处理

- 飞书没有旧版正式配置，因此不执行旧格式迁移。
- 如果 `chatModes.feishu` 不存在，创建默认 10 会话。
- 如果已保存的飞书状态无法验证，将原值原样备份到 `chatMigration.feishu.invalidSaved`，写入恢复日期和错误说明，再原子写入默认状态。
- UI 显示一次可关闭的恢复警告；备份不会通过通用设置 IPC 暴露。
- 无效抖音 URL、站外跳转、错误 partition、跨平台 IPC、版本冲突和持久化失败都显示明确错误，不伪装为成功。
- 保存失败时保持上一份已提交状态，不广播失败数据。
