# 微信公众号扫码登录最小真实验证设计

日期：2026-09-25

## 目标

在不修改正式登录功能的前提下，使用微信公众平台接口测试号、本地 Node.js 验证服务和 Cloudflare 临时 HTTPS 隧道，真实验证以下完整链路：桌面端创建一次性登录会话、后端生成公众号带参数临时二维码、手机微信扫码、微信服务器推送扫码事件、后端校验并关联会话、验证页自动进入成功状态。

本设计只验证微信公众号扫码登录方案 A 的技术可行性。验证通过后，另行设计正式服务号、长期公网后端以及 Electron 登录页接入。

## 已确认选择

- 用户当前没有已认证服务号、微信开放平台网站应用、公网域名或正式后端。
- 第一阶段使用微信公众平台接口测试号，不伪造微信扫码结果。
- 验证后端运行在本机，公网回调通过已安装的 `cloudflared` 临时隧道提供。
- 第一阶段采用“扫码后立即登录”，不增加微信内二次确认页。
- 实验代码与正式登录功能隔离；真实链路通过前不修改 `WxLoginView.vue`。
- 只有收到并验证微信服务器的真实扫码事件，才判定可行性验证成功。

## 当前项目基线

项目已有账号密码登录页面和微信扫码页面：

- `LoginView.vue` 使用旧远程接口完成账号密码、验证码和离线进入。
- `WxLoginView.vue` 从旧接口获取二维码 URL，并每 2.5 秒轮询一次登录令牌。
- 主进程可将令牌与当前设备指纹绑定后保存在本地。

现有微信扫码页只是连接旧接口的客户端外壳；仓库中没有归属于本项目的微信公众号回调服务、带参二维码生成服务或一次性会话系统。因此旧页面不能作为方案 A 已可用的证据。

## 技术方案比较

### 方案 1：本地 Node.js 服务和 Cloudflare 临时隧道

本轮采用。优点是无需先购买服务器或域名，可以用真实微信回调验证完整链路；缺点是隧道地址临时变化，只适合实验，不能作为生产服务。

### 方案 2：Cloudflare Worker 和云端存储

可直接形成持续在线的云端后端，但会提前引入云账号、部署和持久化设计，不符合本轮最小验证范围。

### 方案 3：云服务器、正式域名和已认证服务号

适合最终上线，但用户当前不具备相应资源。只有最小验证通过并决定正式发布时才进入该阶段。

## 结构与边界

### 实验目录

新增隔离目录 `tools/wechat-auth-poc/`，包含：

- 本地 HTTP 服务入口。
- 微信 API 客户端。
- 微信回调签名校验和事件解析。
- 内存登录会话仓库。
- 极简验证页面。
- 示例环境变量文件和独立运行说明。

正式 Vue 页面、Electron 主进程和已有鉴权 IPC 本轮保持不变。

### 网络边界

- 本机服务监听回环地址，供本地验证页创建会话、获取二维码和轮询状态。
- 只有微信回调路径通过临时 HTTPS 隧道暴露给公网。
- 公网回调不提供创建会话、读取任意会话或调试信息的能力。
- 隧道关闭后，临时公网地址立即失效。

### 密钥边界

- 测试号 `AppID`、`AppSecret` 和回调 Token 只存放在本机 `.env`。
- `.env` 必须被 Git 忽略；仓库只提供不含真实值的 `.env.example`。
- `AppSecret` 不进入 Vue、Electron 主进程、渲染进程、安装包、浏览器页面或日志。
- 用户无需把 `AppSecret` 粘贴到聊天中。

## 登录数据流

1. 验证页面向本地服务请求创建登录会话。
2. 服务生成随机、不可预测、短时有效的 `sessionId` 和二维码场景参数。
3. 服务使用测试号凭据获取微信接口访问令牌，并申请带场景参数的临时二维码。
4. 验证页面显示微信返回的真实二维码，并轮询本机会话状态。
5. 用户使用手机微信扫码。未关注测试号时可能先进入关注流程；已关注时直接产生扫码事件。
6. 微信服务器请求临时 HTTPS 回调地址。
7. 服务校验回调签名并解析事件；只接受与有效会话匹配的关注扫码或已关注扫码事件。
8. 服务把会话状态从 `waiting` 更新为 `scanned`，完成一次性消费后更新为 `success`。
9. 验证页面轮询到成功状态，展示脱敏用户标识，并停止轮询。
10. 会话一旦成功、过期或被消费，不能再次签发成功结果。

## 会话状态

- `initializing`：正在连接本地验证服务或创建会话。
- `waiting`：二维码已生成，等待微信扫码。
- `scanned`：收到真实扫码事件，正在关联并消费会话。
- `success`：会话匹配并完成一次性登录验证。
- `expired`：超过 5 分钟未完成，必须刷新二维码。
- `error`：配置、微信接口、签名、事件解析、隧道或网络异常。

页面为错误状态提供中文原因；二维码过期后显示遮罩和“刷新二维码”，不得继续沿用原会话。

## 安全规则

- 登录会话默认有效期为 5 分钟。
- 会话 ID 和场景参数必须使用加密安全随机源生成，不使用连续数字或可猜测时间戳。
- 微信回调必须验证 `signature`、`timestamp` 和 `nonce`；验证失败不解析为有效登录事件。
- 只接受预期的事件类型和场景参数，未知事件返回空响应且不改变会话。
- 同一会话只能成功一次；重复扫码、重复推送和重放请求不能重复消费。
- 第一阶段只在内存保存会话，服务重启后全部失效。
- 不收集微信昵称、头像、手机号或其他个人资料。
- 日志不得输出完整 OpenID、AppSecret、访问令牌、二维码 ticket 或完整会话 ID。
- 验证页只获得有限状态和脱敏标识，不获得微信密钥或完整 OpenID。
- 公网回调快速响应；耗时操作不得阻塞微信回调。

## 错误处理

- 缺少环境变量：启动即停止并逐项显示缺失配置。
- 获取微信访问令牌失败：显示微信错误码和不含密钥的中文说明。
- 生成二维码失败：会话进入 `error`，不显示伪造二维码。
- 回调签名错误：返回拒绝结果并记录脱敏审计信息。
- 隧道断开：验证页显示“公网回调不可达”，不把本地服务在线误报为链路可用。
- 二维码过期：原会话永久失效，刷新时创建新会话和新二维码。
- 重复事件：幂等处理，不重复改变成功结果。
- 未关注和已关注两类扫码事件：统一提取场景参数后匹配会话。

## 验收标准

只有以下七项全部满足，才宣布最小真实验证通过：

1. 测试号成功返回带参数的临时二维码。
2. 手机微信可以正常识别并扫描该二维码。
3. 微信服务器真实请求临时 HTTPS 回调。
4. 回调签名校验通过。
5. 扫码事件中的场景参数准确关联当前电脑会话。
6. 验证页面无需手工刷新，从“待扫码”自动进入“成功”。
7. 过期二维码、重复扫码和伪造回调均不会误判成功。

仅显示二维码、仅打开公众号、仅看到本地服务运行或仅收到未经校验的请求，都不能算验证通过。

## 验证顺序

1. 创建微信公众平台接口测试号，取得测试用 AppID 和 AppSecret。
2. 启动隔离的本地验证服务。
3. 启动 `cloudflared` 临时 HTTPS 隧道，取得临时公网回调地址。
4. 在测试号后台配置回调 URL、Token 和消息加解密方式。
5. 完成微信服务器的首次回调 URL 校验。
6. 在本地验证页创建会话并显示真实带参二维码。
7. 使用手机微信扫码并观察回调、会话和页面状态。
8. 补做过期、重复扫码和伪造签名验证。
9. 停止本地服务和隧道，确认临时入口失效。

## 后续正式化边界

最小验证通过后，仍不能直接宣布生产登录完成。正式化至少需要：

- 申请并认证正式服务号。
- 部署稳定、可监控的长期 HTTPS 后端。
- 使用持久化会话存储并设置可靠的过期清理。
- 设计正式应用账号与微信 OpenID 的绑定关系。
- 增加一次性令牌交换、撤销、退出登录和设备策略。
- 决定是否增加微信内“确认登录”二次确认。
- 将新接口接入 `WxLoginView.vue`，并移除或迁移旧占位接口。
- 停止在本地明文记忆账号密码，迁移到更安全的凭据策略。

这些内容不属于本轮隔离可行性验证。
