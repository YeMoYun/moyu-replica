# 手机投屏模式设计规格

日期：2026-09-23  
状态：原生功能已验收；Electron 开发态集成方案已于 2026-09-24 获用户确认

## 目标

在摸鱼大师中新增“手机投屏模式”，以定制版 QtScrcpy 作为独立原生子程序运行。保持 QtScrcpy 已有的安卓投屏、键鼠控制和设备工具栏能力，同时在 QtScrcpy 主控制窗口与每个手机投屏窗口上增加与摸鱼大师一致的原生控制条。

本模式只支持 Android 11 及以上系统提供的“无线调试 → 使用配对码配对设备”流程。配对、连接、投屏和控制全过程均不依赖 USB，也不提供 USB 功能。

本功能第一阶段只面向 Windows。现有阅读、网页、视频透明度、广告和伪装模式均不修改。

## 已选择的集成方式

采用 QtScrcpy 源码级定制并由 Electron 主进程启动的方式：

- QtScrcpy 继续负责 ADB、视频解码、OpenGL 渲染、设备输入与多设备窗口。
- Electron 只负责主页入口、子进程生命周期、本地 IPC 和整体老板键联动。
- 不把 Qt 视频画面嵌入 `BrowserWindow`。
- 不使用悬浮在第三方窗口上方的独立覆盖层。

这样可以保留 QtScrcpy 的成熟能力，并让控制条真正属于 Qt 窗口，避免外部覆盖层在移动、缩放、全屏和多显示器下错位。

## 主页入口

修改 `src/renderer/src/views/HomeView.vue`：

- 将“游戏模式”分组改名为“游戏与投屏”。
- 保留“单机模式”。
- 新增“手机投屏模式”按钮。
- 点击按钮通过受限 preload bridge 请求 Electron 主进程启动或恢复 QtScrcpy。

启动规则：

- QtScrcpy 未运行时启动一个子进程。
- QtScrcpy 已运行时不创建第二个进程，而是请求它恢复并置前主控制窗口。
- 启动文件缺失、启动失败或 IPC 不可用时，在主页现有错误区域显示中文错误，不让主进程崩溃。

## 原生源码布局

建议把固定版本的 QtScrcpy 源码放入：

```text
native/QtScrcpy/
```

目录中保留上游 `LICENSE`、版权信息和必要的 `NOTICE` 文件，并新增修改说明。修改过的上游文件需要明确注明变更。构建产物不作为普通源码提交，开发态路径和正式打包路径由启动器分别解析。

Electron 侧新增独立模块，例如：

```text
src/main/phone-mirror-launcher.mjs
src/main/phone-mirror-ipc.mjs
```

避免继续膨胀 `src/main/index.js`。

## MoyuControlBar

在 Qt 侧新增可复用的 `MoyuControlBar` QWidget，分别安装到：

1. QtScrcpy 主控制窗口 `Dialog` 顶部。
2. 手机投屏窗口 `VideoForm` 顶部。

视觉要求：

- 深色、紧凑、无原生厚重边框。
- 图标顺序、颜色和交互反馈对齐用户提供的摸鱼大师控制条截图。
- 空白区域可拖动无边框窗口。
- 隐藏控制条后保留清晰的恢复入口。
- 控制条高度计入布局，投屏画面使用剩余区域，不遮挡画面。

共同按钮及行为：

- 隐藏／恢复操作栏。
- 关闭当前窗口。
- 置顶／取消置顶。
- 窗口适配与恢复。
- 调节窗口透明度。
- 开启／关闭鼠标移出隐藏。
- 进入／退出全屏。
- 打开帮助。
- 打开外观相关入口。

主控制窗口专属映射：

- “控”：激活最近使用的手机投屏窗口；没有活动设备时显示“请先连接并启动设备”。
- 主页图标：通过本地 IPC 恢复并置前摸鱼大师主窗口。

手机投屏窗口专属映射：

- “控”：显示／隐藏 QtScrcpy 原有 `ToolForm` 侧边手机控制栏。
- 主页图标：调用 QtScrcpy 设备接口发送 Android Home 指令。
- 窗口适配：保持设备宽高比，并让画面自动占满控制条之外的可用区域。

QtScrcpy 原 `ToolForm` 保留，用于返回、主页、任务切换、音量、旋转、截图等手机操作，不用新控制条替换。

## 状态模型

Qt 侧使用 `QSettings` 保存窗口状态，并按窗口角色和设备序列号隔离：

- 主控制窗口状态独立。
- 每个投屏窗口状态独立。
- 保存尺寸、透明度、置顶和鼠标移出隐藏设置。
- 不恢复旧屏幕坐标。
- 新建或重新打开的窗口在当前显示器工作区中央出现，并短暂置前以保证可见。

隐藏控制条和隐藏窗口是两个独立状态，不能相互覆盖。退出全屏后恢复进入全屏前的正常尺寸。

## 纯无线配对与连接

QtScrcpy 主控制窗口提供“无线连接”入口。点击后打开一个模态的原生 `WirelessPairDialog`，在独立窗口中完成两步无线配对与连接，全程不弹出终端。该窗口由 QtScrcpy 主窗口管理，关闭时必须取消仍在运行的 ADB 操作。

界面与 ADB 执行职责分离：

- `WirelessPairDialog`：负责字段、步骤切换、按钮状态和中文结果展示。
- `WirelessAdbController`：通过 `QProcess` 执行配对、连接、刷新和取消。
- `AdbResultTranslator`：把 ADB 输出转换为中文状态与错误，并生成脱敏诊断信息。

### 第一步：配对设备

用户在手机的“无线调试 → 使用配对码配对设备”页面读取并填写：

- 配对 IP。
- 配对端口。
- 六位数字配对码。
- “开始配对”按钮。
- “我已配对，直接连接”入口。

配对码输入框默认隐藏内容并提供显示／隐藏按钮。界面明确提示“配对端口与连接端口可能不同”。点击“开始配对”后，QtScrcpy 调用：

```text
adb pair <IP>:<配对端口>
```

ADB 请求配对码时，`WirelessAdbController` 通过 `QProcess::write()` 将六位码写入标准输入，不把配对码放入命令行参数。配对成功后立即清空配对码并自动切换到第二步；IP 自动带入，配对端口不带入。

配对码不写入配置、不写入日志、不在错误或诊断信息中回显，也不出现在进程参数中。

### 第二步：连接设备

用户在手机无线调试主页读取并填写连接 IP 与连接端口。第二步提供“连接设备”和“返回重新配对”按钮。点击“连接设备”后调用：

```text
adb connect <IP>:<连接端口>
```

成功后显示“设备连接成功”，自动刷新设备列表，并由用户点击“完成”关闭配对窗口。回到主窗口后，用户选择设备并沿用 QtScrcpy 原有启动投屏流程。已经完成过配对的手机可以从第一步选择“我已配对，直接连接”。

连接区只记住上次使用的 IP 地址。配对码不保存；端口保持可编辑，不把历史端口视为当前有效值。

### 中文状态与错误反馈

界面不直接把 ADB 英文输出作为主消息，而是展示中文状态和下一步建议：

- 正在配对：`正在配对设备，请保持手机配对页面开启……`
- 配对成功：`配对成功，请填写无线调试主页中的连接端口`
- 正在连接：`正在连接设备……`
- 连接成功：`设备连接成功，设备列表已刷新`
- 已经配对：`该设备已经配对，可以直接连接`
- 配对码错误或失效：`配对码不正确或已经失效，请在手机上重新生成`
- 配对超时：`配对超时，请确认手机配对页面仍然开启`
- 网络不可达：`无法访问手机，请确认电脑与手机处于同一网络`
- 连接端口错误：`连接端口无效，请填写无线调试主页显示的端口`
- 连接被拒绝：`手机拒绝连接，请确认无线调试仍然开启`
- 设备离线：`设备已离线，请重新连接`
- ADB 缺失：`无线调试组件缺失，请重新安装或修复摸鱼大师`
- 未分类失败：`操作失败，请重试；如仍失败，可复制诊断信息`

界面提供默认折叠的“诊断信息”。其中可保留脱敏后的 ADB 原始输出用于排查，但不得包含配对码；诊断信息不主动写入文件。配对或连接执行期间禁用相关输入和按钮，防止并发命令。

### 去除 USB 入口

产品界面不提供 USB 连接，不执行 `adb tcpip 5555`，并隐藏或移除上游所有依赖 USB 的快捷入口，包括：

- USB 设备连接入口。
- 需要先插入 USB 的 WIFI 连接快捷操作。
- “启动 adbd”。
- 通过 USB 获取设备 IP。

保留分辨率、码率、录制、多设备投屏等与连接媒介无关的 QtScrcpy 高级选项。第一版不实现二维码配对，也不自动扫描局域网。

### 输入与命令状态

- IP 或主机地址不能为空。
- 端口必须是 `1` 到 `65535` 的整数。
- 配对码必须是六位数字。
- ADB 必须通过 `QProcess` 程序名和参数列表启动，不拼接 Shell 命令字符串，不创建控制台窗口。
- 同一时刻只允许执行一个配对或连接命令，执行期间禁用对应按钮。
- 配对命令超时为 30 秒，连接命令超时为 15 秒；超时后终止当前 ADB 子进程并恢复界面操作。
- 关闭配对窗口或主窗口时终止尚未完成的配对或连接进程。
- 命令输出进入界面或日志前必须移除配对码。

错误提示需要区分：配对码错误、配对或连接超时、网络不可达、连接端口错误或变化、设备 `offline`。配对成功但连接失败时，不自动重新配对，而是提示用户检查无线调试主页中的当前连接端口。

## 本地 IPC 与生命周期

Electron 和 QtScrcpy 使用仅限本机的命名管道通信。Electron 启动子进程时传入随机会话标识和父进程信息，不开放网络端口。

最小消息集合：

- `focus-main-app`：Qt 请求恢复摸鱼大师主窗口。
- `focus-qtscrcpy-main`：Electron 请求恢复 QtScrcpy 主控制窗口。
- `boss-hide`：隐藏全部 QtScrcpy 窗口。
- `boss-show`：恢复老板键触发前可见的 QtScrcpy 窗口。
- `shutdown`：摸鱼大师正常退出时请求 QtScrcpy 清理并退出。

生命周期规则：

- 关闭 QtScrcpy 主控制窗口不强制断开或关闭正在投屏的窗口，保留上游托盘行为。
- 摸鱼大师整体退出时关闭所启动的 QtScrcpy 子进程，避免残留后台进程。
- 子进程异常退出时释放句柄并允许下次重新启动。
- Electron 退出期间不再自动重启子进程。

## 鼠标移出隐藏

Qt 窗口不能依赖 Electron 的窗口控制器。由 `MoyuControlBar` 所属窗口维护自动隐藏状态：

- 开启后使用短周期计时器读取全局光标位置。
- 光标离开窗口边界后将窗口透明度降为隐藏状态。
- 光标重新进入保存的窗口边界后恢复用户设定透明度。
- 无线配对、帮助、透明度弹窗和系统菜单打开时暂时禁止自动隐藏。
- 老板键隐藏优先于自动隐藏，恢复老板键时不得错误显示此前本就隐藏的窗口。

## 可行性验证顺序

第一阶段只验证最短的纯无线真实链路：

1. 使用已经构建并发布到隔离目录的 QtScrcpy v4.1.0 及其内置 ADB。
2. 全程不连接 USB，在 Android 11 及以上手机上打开无线调试和配对码页面。
3. 手动执行一次 `adb pair`，再使用无线调试主页显示的独立端口执行 `adb connect`。
4. 在未修改的 QtScrcpy 中选择无线设备并启动投屏。
5. 验证画面、鼠标点击、键盘输入和窗口缩放。
6. 断开并重新连接，验证已经配对的手机可以跳过配对步骤直接连接。

该纯无线链路已于 2026-09-23 验证为 PASS。只有这条链路成功后才开始无线连接界面、控制条和 Electron 集成。探针期间用户只需临时提供手机当次显示的配对地址、六位配对码和连接地址；这些值不得写入项目文件。

## 分阶段实施

### 阶段 A：上游基线

- 获取并固定 QtScrcpy 源码版本。
- 保留许可证和修改说明。
- 构建未修改版本并完成一台真机的纯无线验证。

### 阶段 B：原生无线连接

- 新增 `WirelessPairDialog`、`WirelessAdbController` 和 `AdbResultTranslator`。
- 在 QtScrcpy 主控制窗口增加“无线连接”入口，以独立两步窗口完成配对和连接。
- 隐藏或移除 USB 入口和所有依赖 USB 的 WIFI 快捷操作。
- 接入输入校验、标准输入传递配对码、命令互斥、超时、输出脱敏和中文分类错误提示。
- 验证首次配对连接、已配对后直接重连和设备列表刷新。

### 阶段 C：Qt 控制条

- 新增 `MoyuControlBar`。
- 先集成一个 `VideoForm` 并验证布局、缩放、透明度、置顶和全屏。
- 复用到 `Dialog`。
- 接通“控”和主页按钮的窗口特定映射。

### 阶段 D：Electron 集成

- 添加主页入口与 preload bridge。
- 添加单实例子进程启动器。
- 建立命名管道 IPC。
- 接通老板键、主窗口恢复和整体退出清理。

阶段 D 作为当前独立验收批次实施，暂不同时修改安装包。开发态启动器按以下顺序解析 QtScrcpy：

1. 测试或开发人员通过 `MOYU_QTSCRCPY_RUNTIME` 显式提供的运行库路径。
2. 当前工作树内已经过真机验收的定制运行库目录。

路径解析、进程启动和 IPC 均只存在于 Electron 主进程；渲染进程仅能通过 preload 暴露的单一“启动或恢复手机投屏”方法发起请求，不能传入任意可执行文件路径或命令行参数。

Electron 启动 QtScrcpy 时创建本次会话专用的随机命名管道，并通过子进程环境传入管道名和会话令牌。QtScrcpy 不开放 TCP 端口。只有令牌匹配的单行 JSON 消息才进入控制分发，未知消息直接忽略。

阶段 D 的单实例范围是“当前摸鱼大师进程所启动的 QtScrcpy”：

- 首次点击按钮时启动子进程。
- 子进程存活时再次点击，只发送 `focus-qtscrcpy-main`。
- 子进程意外退出后清理状态，下一次点击允许重新启动。
- 摸鱼大师退出时先发送 `shutdown`，短暂等待正常退出；超时后只结束本次启动并持有句柄的进程树。
- 用户在摸鱼大师之外手动启动的 QtScrcpy 不纳入本批次管理，也不会被退出清理误杀。

老板键继续由 Electron 保持唯一权威状态。主窗口隐藏后发送 `boss-hide`；恢复后发送 `boss-show`。QtScrcpy 只恢复老板键触发前可见的窗口，不能把用户原本关闭或隐藏的窗口强制显示出来。

本批次完成标准：主页入口可启动或恢复 QtScrcpy、Qt 主页按钮可恢复摸鱼大师、老板键联动正确、主程序退出无本批次产生的残留 QtScrcpy 进程。通过后再进入阶段 E。

### 阶段 E：打包

- 将 QtScrcpy 可执行文件、Qt 插件、ADB、服务端文件和许可证作为 Electron 额外资源打包。
- 开发态和正式包均通过明确路径启动。
- 在无开发工具的干净 Windows 环境进行一次安装包启动验证。

## 最小验证范围

遵循第一性原理，不先建立大规模自动化矩阵。每阶段只验证其最高风险点：

- Node 单元测试：启动路径解析、单实例、退出清理和错误消息。
- Qt 小范围测试：地址与端口校验、配对码校验、ADB 参数与标准输入映射、中文错误翻译、输出脱敏、状态键隔离和按钮命令映射。
- Electron 冒烟：主页按钮能启动或恢复子程序。
- 一次全程无 USB 的真机人工验证：配对、连接、直接重连、投屏、输入、缩放、控制条、原侧边栏、老板键和退出清理。

## 非目标

本轮不包括：

- 重写 QtScrcpy 的视频解码或 ADB 核心。
- 将手机画面嵌入 Electron DOM。
- 修改现有透明度模式。
- 支持 iPhone。
- USB 调试、USB 连接或以 USB 启动无线 ADB。
- Android 10 及以下设备的无线连接兼容方案。
- 二维码配对和局域网自动发现。
- 第一阶段支持 macOS 或 Linux。

## 正式实施边界

正式实现分为三个可独立验收的批次：

1. Qt 原生功能：将固定上游源码纳入 `native/QtScrcpy`，完成原生无线配对窗口、中文反馈、USB 入口移除，以及主控制窗口和手机投屏窗口的 `MoyuControlBar`，随后用真实手机验收。
2. 摸鱼大师开发态集成：完成主页入口、单实例启动或恢复、本地 IPC、老板键和生命周期清理。
3. 安装包集成：将已验收运行库纳入额外资源，并在干净 Windows 环境验证安装版。

第一批已经通过。当前只实施第二批，验收后再开始第三批，避免把开发态通信问题与安装包资源问题混在一起。现有透明模式和其他已验收功能均不修改。
