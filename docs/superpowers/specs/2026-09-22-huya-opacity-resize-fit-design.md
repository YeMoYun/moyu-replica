# 虎牙透明模式窗口缩放自适应设计

## 目标

修复虎牙透明模式在调整原生窗口大小后，网页内容仍保持旧缩放比例、需要继续上下滚动才能查看的问题。

## 已确认行为

- 虎牙透明模式每次检测到网页容器尺寸变化时，都重新按照当前可用宽高计算缩放比例。
- 即使用户此前选择过手动网页缩放，下一次调整窗口大小也会由自动适配接管。
- 自动适配结果写回虎牙自己的 `huyaOpacity.zoom` 与 `huyaOpacity.autoFit` 设置，刷新、页面跳转和重新打开后的状态保持一致。
- 用户仍可临时选择手动缩放；只要窗口尺寸没有再次变化，手动比例继续生效。

## 修改边界

- 只改变 `huyaOpacity` 的窗口尺寸变化处理。
- B站、快手、抖音、斗鱼及阅读透明模式保持现有行为。
- 不修改虎牙网页结构，不强制拉伸单个播放器节点，不改变现有控件布局。

## 实现方式

复用现有 `ResizeObserver -> page.resize()` 链路。在共享透明视频控制器中按平台区分：

- 虎牙：只要页面已准备好，`resize()` 就重新计算适配比例并以 `autoFit: true` 应用。
- B站和快手：继续仅在用户已开启自动适配时响应尺寸变化。

这样无需增加第二套窗口监听，也不会把虎牙站点细节散落到 Vue 视图中。

## 异常与并发

- 继续使用现有串行任务队列和文档代次检查，避免页面跳转期间把旧页面尺寸应用到新页面。
- 设置保存失败时沿用现有回滚逻辑，恢复调整前的显示比例并展示既有错误反馈。
- 页面未准备好时忽略尺寸变化，等待 `dom-ready` 完成首次适配。

## 验收与回归测试

新增针对性测试：

1. 虎牙先选择手动缩放，再改变网页容器尺寸并调用 `resize()`。
2. 验证缩放比例按新尺寸重新计算。
3. 验证 `autoFit` 变为 `true`，虎牙设置同步更新。
4. 验证 B站和快手仍保留手动缩放，不受此次修复影响。
