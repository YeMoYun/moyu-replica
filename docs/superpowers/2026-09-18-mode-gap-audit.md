## 功能支持边界

1. 先覆盖此前验收的应用：抖音、B站、虎牙、快手、微信读书、番茄、晋江。斗鱼控制器已在项目中，本轮同时列出差距，独立验收。
2. 源首页明确提供微信读书的广告/聊天选择；番茄、晋江在核查到的源首页直接打开阅读，未提供同样的五模式选择。因此为它们补广告/聊天属于用户要求的扩展，不宣称源软件已有。复用阅读能力但需要各站点单独验证。
3. 飞书是本地伪装聊天界面，不是登录或控制真实飞书客户端；微信、钉钉同理。不会发送消息给真实联系人。
4. 不在这一批扩展本地书籍、游戏、Excel、任意窗口绑定、账户/支付/遥测系统。原软件的广告外链和遥测不照搬。

## 核查中需要纠正/确认的细节

- 聊天视频老板键不是隐藏整个窗口，而是按横/竖屏替换不同动态图，之后恢复同一播放器。
- 源微信/钉钉处理微信读书时走独立的阅读遮挡分支，并暂停/恢复自动滚动，不能直接把视频 GIF 策略套给阅读。下一批阅读聊天设计需核对其模板遮挡外观。
- 教程首页等待遮挡写有 30 秒，而截图提示 10 秒；暂不纳入已确认参数。
- 教程的 B站 J/K 快进/快退描述前后冲突。以源事件处理与实测为准，不凭文案确定映射。
- PDF 为静态导出，不能验证动画时序、拖动手感或播放器在真实站点的全部响应；需要源资源/交互与后续实测补充。

## 推荐实施顺序与验收门槛

### 第一批：广告与模式交接基础（G01–G04、G12–G13）

先以抖音视频广告与微信读书阅读广告各打通一个代表，再扩展 B站/虎牙/快手和番茄/晋江。老板键使用按窗口模式分派的独立策略，而不是修改透明视图去兼容所有模式。新模式选择接口支持五种模式，但正式界面不得让未完成的聊天模式静默落到旧实现；未完成时明确提示。

验收：专属广告控件、真实关窗、遮挡恢复、链接交接、设置重启恢复；已验收透明功能回归无变化。

### 第二批：B站与直播控制器（G10–G11）

补真实列表/房间/账号状态与播放模式联动。登录由用户完成，遇到权限或站点限制明确显示，不模拟真实账户数据。

验收：视频选择和房间号能交给对应模式；空房间号进首页；未登录、无数据、失败状态准确。

### 第三批：三套聊天 UI 轻量网页验收（G05–G09 的视觉与交互预览）

只在独立预览目录制作 HTML/CSS/JS，不改正式 `ChatSkinView.vue`、`ChatConfigView.vue`、路由、preload 或聊天主进程代码。微信/钉钉对照只读源布局；飞书作为新增方案独立标注。无框架或重依赖，不连接真实账户。

预览覆盖：会话切换、发送演示消息、插入演示播放器、横/竖屏、大小、自/对方发送、遮罩、老板键前后状态、设置和配置面板、不同窗口尺寸。演示数据与播放器占位必须标明，不把它当作真实播放功能。

用户分别验收三套 UI；有反馈则修订网页。没有明确通过之前，不移植正式代码。

### 第四批：聊天行为与正式集成（G05–G09、G12–G13）

UI 通过后，将已批准布局接入真实播放器/阅读页，完成聊天数据、配置同步与迁移、持久化、快捷键、遮挡恢复、五模式入口与跨模式交接。共享聊天行为但三个外观与配置独立。

验收：界面与批准网页一致；站点与消息功能实际工作；老板键策略正确；重启配置保持；全套保护性回归及新模式烟测通过。

## 方案选择

- 推荐：独立广告视图 + 分模式老板键策略 + 共享聊天行为/三套独立皮肤。对已验收功能影响范围较小，便于逐批定位问题。
- 替代：继续扩大 `SiteView.vue` 与 `ChatSkinView.vue` 的条件分支。文件少，但更易再次混入旧控件和错误遮挡逻辑，不推荐。
- 替代：整体重写全部模式。统一性更强，但会扩大已验收功能的回归范围，本轮不采用。

本清单供确认范围与验收顺序；不是各批详细设计的最终批准。每批按明确设计和验收点推进，聊天 UI 另有强制网页验收门槛。
